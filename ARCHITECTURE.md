# Arquitetura do Sistema — Kilo Notes (V2)

Aplicação web minimalista de Bloco de Notas com **armazenamento comprimido em banco Oracle Database** e **entrega 100% lossless na leitura**, utilizando **Python (Flask + `oracledb` Thin Mode + `Pillow` + `zlib`)** no backend e **HTML5 + CSS3 + TypeScript (Vanilla JS)** no frontend, preparada para deploy contínuo no **Render** via **GitHub**.

## 2. DDL SQL — Oracle Database

Projetado para **Oracle Database (12cR2 / 19c / 21c / 23ai)** com `GENERATED BY DEFAULT AS IDENTITY`, armazenamento `SECUREFILE` para `BLOB` e limpeza automática de imagens via `ON DELETE CASCADE` + limpeza de imagens órfãs quando removidas do corpo da nota.

```sql
-- ============================================================================
-- 1. TABELA DE NOTAS (Conteúdo HTML/Texto comprimido via zlib nível 9)
-- ============================================================================
CREATE TABLE NOTES (
    ID               NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    TITLE            VARCHAR2(255 CHAR) DEFAULT 'Sem título' NOT NULL,
    CONTENT_ZLIB     BLOB,
    RAW_TEXT_BYTES   NUMBER(12) DEFAULT 0 NOT NULL,
    COMP_TEXT_BYTES  NUMBER(12) DEFAULT 0 NOT NULL,
    CREATED_AT       TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL,
    UPDATED_AT       TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL
)
LOB (CONTENT_ZLIB) STORE AS SECUREFILE (
    ENABLE STORAGE IN ROW
    CHUNK 8192
    NOCACHE
    LOGGING
);

CREATE INDEX IDX_NOTES_UPDATED_AT ON NOTES (UPDATED_AT DESC);

-- ============================================================================
-- 2. TABELA DE IMAGENS DAS NOTAS (Convertidas para WebP 1280px q=72 method=6)
-- ============================================================================
CREATE TABLE NOTE_IMAGES (
    ID               NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    NOTE_ID          NUMBER NOT NULL,
    IMAGE_WEBP       BLOB NOT NULL,
    WIDTH            NUMBER(5) NOT NULL,
    HEIGHT           NUMBER(5) NOT NULL,
    RAW_IMAGE_BYTES  NUMBER(12) NOT NULL,
    COMP_IMAGE_BYTES NUMBER(12) NOT NULL,
    SHA256_HASH      VARCHAR2(64 CHAR),
    CREATED_AT       TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL,
    CONSTRAINT FK_NOTE_IMAGES_NOTE
        FOREIGN KEY (NOTE_ID)
        REFERENCES NOTES (ID)
        ON DELETE CASCADE
)
LOB (IMAGE_WEBP) STORE AS SECUREFILE (
    ENABLE STORAGE IN ROW
    CHUNK 8192
    NOCACHE
    LOGGING
);

-- Índice obrigatório na FK para evitar table lock em DELETE CASCADE e acelerar agregações
CREATE INDEX IDX_NOTE_IMAGES_NOTE_ID ON NOTE_IMAGES (NOTE_ID);
```

> **Nota sobre `ENABLE STORAGE IN ROW`:** No Oracle SecureFiles, payloads comprimidos menores que ~4 KB ficam armazenados diretamente inline na linha da tabela, evitando alocação de blocos LOB extras e economizando ainda mais tablespace.

## 3. Arquitetura do Pool `oracledb` e Pipeline de Compressão

### 3.1. Pool de Conexões `oracledb` (Exclusivamente Thin Mode)

O driver oficial `python-oracledb` opera em **Thin Mode** por padrão (sem qualquer chamada a `oracledb.init_oracle_client()`), comunicando-se diretamente via protocolo TTC sobre TCP/TLS sem depender do Oracle Instant Client:

```text
[Gunicorn Workers] ---> [oracledb.ConnectionPool (Thin Mode)] ---> [Oracle Database]
                         min=1, max=4, increment=1
                         ping_interval=60, timeout=120
                         fetch_lobs=False (streaming direto de bytes)
```

- **`oracledb.defaults.fetch_lobs = False`**: Configurado globalmente para que colunas `BLOB` retornem diretamente como `bytes` nativos do Python sem round-trips adicionais de cursores LOB para payloads de notas e imagens.
- **Gerenciamento de Contexto**: Cada requisição obtém uma conexão do pool via `with pool.acquire() as conn:`, garantindo devolução imediata ao pool e commit/rollback atômico.

### 3.2. Pipeline de Compressão de Texto (`zlib`)

1. **Entrada:** String HTML/Markdown da nota enviada pelo editor.
2. **Codificação:** Conversão para `bytes` UTF-8 (`raw_bytes = len(utf8_data)`).
3. **Compressão:** `comp_data = zlib.compress(utf8_data, level=9)` (`comp_bytes = len(comp_data)`).
   - Redução típica em texto/HTML estruturado: **70% a 85%**.
4. **Leitura:** `zlib.decompress(blob_bytes).decode("utf-8")` (com fallback seguro caso `CONTENT_ZLIB` seja nulo/vazio).

### 3.3. Pipeline de Compressão de Imagem (`Pillow`)

```text
[Clipboard Ctrl+V (PNG/BMP/JPEG)]
       │ (raw_image_bytes medido no buffer original)
       ▼
[Pillow Image.open(BytesIO)]
       │ 1. ImageOps.exif_transpose() (corrige orientação)
       │ 2. Normalização de canal: RGBA (se tiver transparência) ou RGB
       │ 3. Downscale proporcional: se width > 1280px -> resize((1280, novo_h), LANCZOS)
       │ 4. Codificação WebP: save(out_buf, format="WEBP", quality=72, method=6)
       ▼
[BLOB WebP Otimizado em NOTE_IMAGES] -> Redução típica de prints PNG: 90% a 97%
```

- **Garbage Collection de Imagens Descartadas:** Ao salvar uma nota (`PUT /api/notes/<id>`), o backend extrai todos os IDs referenciados em `/api/images/<id>` no corpo da nota e executa `DELETE FROM NOTE_IMAGES WHERE NOTE_ID = :note_id AND ID NOT IN (...)`, garantindo que prints apagados pelo usuário durante a edição não fiquem órfãos no banco.

### 3.4. Cálculo da Métrica de Economia

Para cada nota, a economia total combina texto + todas as imagens vinculadas:
- `raw_total = RAW_TEXT_BYTES + COALESCE(SUM(RAW_IMAGE_BYTES), 0)`
- `saved_total = COMP_TEXT_BYTES + COALESCE(SUM(COMP_IMAGE_BYTES), 0)`
- `reduction_pct = round((1 - (saved_total / raw_total)) * 100, 1)` (quando `raw_total > 0`)
- Exibição na UI: `Original: 2.4 MB → Salvo: 95 KB (-96.0%)`

## 4. Contratos das Rotas REST

Todas as rotas `/api/*` exigem sessão autenticada via `Flask-Login` (`401 Unauthorized` se não autenticado).

### 4.1. `GET /api/notes`
Lista todas as notas (sem trafegar o `BLOB` de conteúdo) ordenadas por `UPDATED_AT DESC`, já com o resumo de economia.
- **Response `200 OK`:**
```json
[
  {
    "id": 12,
    "title": "Troubleshooting Oracle Listener",
    "updated_at": "2026-11-20T03:45:10Z",
    "metrics": {
      "raw_bytes": 2516582,
      "compressed_bytes": 97280,
      "saved_percent": 96.1,
      "image_count": 4
    }
  }
]
```

### 4.2. `POST /api/notes`
Cria uma nova nota em branco ou com título/conteúdo inicial.
- **Request JSON:**
```json
{
  "title": "Nova Nota",
  "content": ""
}
```
- **Response `201 Created`:** Mesmo contrato do `GET /api/notes/<id>`.

### 4.3. `GET /api/notes/<id>`
Carrega uma nota específica, descomprimindo `CONTENT_ZLIB` em memória.
- **Response `200 OK`:**
```json
{
  "id": 12,
  "title": "Troubleshooting Oracle Listener",
  "content": "<p>Print do erro:</p><img src=\"/api/images/45\" width=\"1280\" height=\"720\">",
  "created_at": "2026-11-20T03:10:00Z",
  "updated_at": "2026-11-20T03:45:10Z",
  "metrics": {
    "raw_text_bytes": 4200,
    "compressed_text_bytes": 1180,
    "raw_image_bytes": 2512382,
    "compressed_image_bytes": 96100,
    "raw_bytes": 2516582,
    "compressed_bytes": 97280,
    "saved_percent": 96.1,
    "image_count": 4
  }
}
```

### 4.4. `PUT /api/notes/<id>`
Atualiza título e conteúdo (comprimindo texto com `zlib`), remove imagens de `NOTE_IMAGES` que não estejam mais referenciadas no HTML da nota e retorna as métricas recalculadas.
- **Request JSON:**
```json
{
  "title": "Troubleshooting Oracle Listener",
  "content": "<p>Texto atualizado...</p><img src=\"/api/images/45\">"
}
```
- **Response `200 OK`:** Objeto `metrics` atualizado + `updated_at`.

### 4.5. `DELETE /api/notes/<id>`
Remove a nota e apaga em cascata (`ON DELETE CASCADE`) todos os `BLOB`s de imagens associados em `NOTE_IMAGES`.
- **Response `204 No Content`**

### 4.6. `POST /api/upload`
Recebe imagem colada via `Ctrl+V` (`multipart/form-data`), processa no pipeline `Pillow` -> `WebP (max 1280px, q=72, method=6)` e grava em `NOTE_IMAGES`.
- **Request `multipart/form-data`:**
  - `note_id`: ID numérico da nota ativa
  - `image`: Arquivo binário (`image/png`, `image/jpeg`, `image/webp`, `image/bmp`)
- **Response `201 Created`:**
```json
{
  "id": 45,
  "url": "/api/images/45",
  "width": 1280,
  "height": 720,
  "raw_bytes": 1450200,
  "compressed_bytes": 48320,
  "saved_percent": 96.7
}
```

### 4.7. `GET /api/images/<id>`
Entrega o binário WebP diretamente do Oracle com cabeçalhos de cache imutável para evitar leituras repetidas do banco.
- **Response `200 OK`:**
  - `Content-Type: image/webp`
  - `Cache-Control: public, max-age=31536000, immutable`
  - `ETag: "img-<id>-<comp_bytes>"`
  - Body: bytes brutos do `IMAGE_WEBP`


**Variáveis de Ambiente Obrigatórias (`.env` / Render Dashboard):**
- `SECRET_KEY`: Chave criptográfica de sessão do Flask.
- `ADMIN_USER`: Login do proprietário do bloco de notas.
- `ADMIN_PASSWORD_HASH`: Hash gerado com `werkzeug.security.generate_password_hash`.
- `ORACLE_USER`: Usuário do schema Oracle.
- `ORACLE_PASSWORD`: Senha do schema Oracle.
- `ORACLE_DSN`: Easy Connect Plus string ou TNS Descriptor (ex: `host:1521/service_name` ou `tcps://adb.sa-saopaulo-1.oraclecloud.com:1522/...`).
- `MAX_CONTENT_LENGTH`: Limite de upload por requisição (padrão `16777216` = 16 MB para prints 4K brutos antes da compressão).

## 6. Plano de Execução em 4 Etapas (Orchestrator / Neon)

Para máxima economia de tokens e validação incremental:

1. **Etapa 1 — Fundação, Configs e Banco (`sql/`, `app/config.py`, `app/db.py`, `.gitignore`, `requirements.txt`, `Procfile`):**
   - Criar arquivos de configuração de deploy, `.gitignore`, `sql/schema.sql` e o módulo de pool de conexões `oracledb` em Thin Mode com auto-verificação de schema/conectividade.
2. **Etapa 2 — Motor de Compressão e Autenticação (`app/compression.py`, `app/auth.py`, `app/__init__.py`, `wsgi.py`):**
   - Implementar os pipelines `zlib` (texto) e `Pillow` (WebP `1280px`, `q=72`, `method=6`), cálculo de métricas e autenticação enxuta via `Flask-Login`.
3. **Etapa 3 — Rotas REST e Entrega Binária com Cache (`app/routes/notes_api.py`, `app/routes/images_api.py`, `app/routes/views.py`):**
   - Implementar CRUD de notas comprimidas, garbage collection de imagens removidas da nota, endpoint `/api/upload` e `/api/images/<id>` com `Cache-Control: public, max-age=31536000, immutable` e suporte a `ETag` (`304 Not Modified`).
4. **Etapa 4 — Frontend Dark Mode e TypeScript (`templates/`, `static/css/dark.css`, `static/ts/*.ts`, `tsconfig.json`, `static/js/*.js`):**
   - Construir a interface escura (Sidebar + Editor + Indicador discreto de economia em tempo real), interceptação de `Ctrl+V` para upload transparente de prints e compilação para `static/js/`.
